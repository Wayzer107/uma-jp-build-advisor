## 2. Re-enable Pi SSH

The trusted host alias is raspberrypi.local. Use the hostname so OpenSSH matches the existing trusted host-key entry:

~~~powershell
ssh <pi-user>@raspberrypi.local
~~~

The current failure is user authentication: Permission denied (publickey,password). The Windows default ED25519 public key is at $env:USERPROFILE\.ssh\id_ed25519.pub; only that public key may be installed on the Pi. Never copy the private key. Add the public key to the Pi user's ~/.ssh/authorized_keys through a trusted local console or another authorized admin path, with .ssh mode 700 and authorized_keys mode 600. Then verify with BatchMode before deployment, replacing `<pi-user>` with the configured Pi account:

~~~powershell
ssh -o BatchMode=yes -o ConnectTimeout=8 <pi-user>@raspberrypi.local "whoami; uname -m; cat /etc/os-release | head -5"
~~~

If the account, key, or SSH host changes, verify the host fingerprint before accepting it.

## 3. Inspect, then install

Before writing to the Pi, check ~/Sources/uma and preserve any existing files. For a new empty target, clone the public repo there:

~~~sh
mkdir -p ~/Sources
git clone https://github.com/Wayzer107/uma-jp-build-advisor.git ~/Sources/uma
~~~

Keep the private repo in a sibling path such as ~/Sources/uma-private. Do not put private files inside the public clone. Configure repository paths through /etc/uma-build-advisor/actions.env or the local config; no local Japanese game root belongs on Pi.

Install Node.js 22 on 64-bit ARM, Python 3, Git, and the official OpenAI tunnel client for the remote MCP plugin. Install Tailscale only if the optional Actions API is being deployed. Build using the checked-in frozen lockfile.

- MCP web: configure and run the OpenAI Secure MCP Tunnel profile, create the tunnel-bound package with Plugin Creator, and verify ChatGPT discovers the reference, inventory, maintenance, and recommendation tools.
- Mobile check: test the connected plugin in the target ChatGPT mobile client. Current Help Center docs say custom MCP apps are web-only; record actual behavior and do not infer support from responsive UI guidance.
- Optional GPT Actions integration: if mobile text access is required and the target client cannot use the MCP app, deploy the read-only Actions service behind HTTPS and configure a separate Custom GPT. Keep the service bound to 127.0.0.1; use 32 random bytes rendered as 64 hex characters and protect the EnvironmentFile; check 401/200 behavior without putting the token in output.
- Optional Tailscale Funnel: if the Actions API is deployed, enable HTTPS and Funnel in the user's tailnet, run the documented Funnel command, and verify the public HTTPS health endpoint and authenticated API from outside the home network.
- Optional Actions integration: if needed, import the OpenAPI schema, replace the example hostname, configure Bearer auth, paste the instructions, enable Web search, and test the created GPT and Actions in a mobile conversation if account/workspace permissions allow it.
- Inventory: if the private repo is not available on Pi, report that ownership is unknown. Do not create sample ownership or fall back to Global/JP data.
